# Ingenious Forge — Component Library

This Storybook documents the UI component library for the Ingenious Forge web application. It covers the 53 Shadcn-based primitives in `src/components/ui/`, the cross-cutting shared components, and the patterns for writing new stories.

---

## Project structure

The web app is organised feature-first. Each domain lives under `src/features/<domain>/` and owns its own `components/`, `hooks/`, `api/`, and `store/` as needed. Only genuinely cross-cutting code belongs in the top-level shared layers:

## Writing a story

Stories live in `src/stories/<category>/` and mirror the source tree. The file must end in `.stories.tsx`.

```tsx
import type { Meta, StoryObj } from "@storybook/react-vite";
import { Button } from "@/components/ui/button";

const meta: Meta<typeof Button> = {
  title: "UI/Button",
  component: Button,
  parameters: { layout: "centered" },
  tags: ["autodocs"],
};

export default meta;
type Story = StoryObj<typeof Button>;

export const Default: Story = {
  args: { children: "Start session" },
};
```

**Conventions**

- Use `title: "UI/<ComponentName>"` for Shadcn primitives and `title: "Features/<Domain>/<ComponentName>"` for feature components.
- Add `tags: ["autodocs"]` to generate a docs page automatically.
- Use real Forge content in story args — "Start session", "View diff", "Delete" rather than generic labels.
- For icon use, import from `lucide-react` at 16 px with a 2 px stroke.

## Theming

The app uses Tailwind CSS v4 with CSS variables for all tokens. Light and dark themes are toggled via a `data-theme` attribute on `<html>`. Storybook's theme toolbar switches between them.

Component variants follow the Shadcn pattern — `variant` and `size` props map to `cva` classes. Add new variants in the component file, not via inline Tailwind classes in stories.
