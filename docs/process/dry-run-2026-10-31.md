## Findings

### ⚠️ Worktree context in Claude pre-tool hooks

The `main-guard.sh` hook resolves the branch correctly when run from the
worktree CWD, but the Claude Code harness's pre-tool context may
intermittently use the main checkout's context. The git hooks are
unaffected. This is low-severity because the git hooks are the hard
enforcement layer and the CI is the final gate. Follow-up: #55, which
makes the hook read the branch of the command's own folder.

### ⚠️ `change-review` not run in a separate session

The working agreements require the builder not to review its own work.
A full `change-review` in a separate session would be the correct process.
For this dry run, the maintainer's PR review serves as the gate.
Follow-up: #59 settled when a separate session is required (application
code) and when the automated reviewer plus the maintainer's review is
enough (process, skill and docs changes).
