This page explains how Roo Code persists and manages state across the extension host, webview UI, and disk. It covers VS Code's storage APIs (globalState, workspaceState, secrets), the `ContextProxy` abstraction that routes writes to the correct store, the `ProviderSettingsManager` for API configuration profiles, `TaskHistoryStore` for per-task history, and the tiered caching architecture for models and metadata.

---

## Storage Layers

Roo Code uses four distinct storage mechanisms provided by the VS Code API and the file system:

| Store | VS Code API | Scope | Used for |
|---|---|---|---|
| `globalState` | `context.globalState` | Extension-global, persists across workspaces | General settings, UI preferences, feature flags, task history index |
| `workspaceState` | `context.workspaceState` | Per-workspace | Workspace-specific toggles like `lockApiConfigAcrossModes` |
| `secrets` | `context.secrets` | Extension-global, encrypted | Sensitive credentials (API keys, tokens) |
| Disk (`globalStorageUri`) | `fs` | Extension-global, file system | Per-task message files, model list cache, task metadata, terminal output spills |

## ContextProxy

`ContextProxy` (`src/core/config/ContextProxy.ts`) is the central orchestrator for state access. It maintains an in-memory cache of `globalState` and `secrets` to provide synchronous access where possible and abstracts the underlying VS Code storage routing.

### Storage Routing Logic
The proxy uses utility functions from `@roo-code/types` to determine where a key should be stored. For example, `isSecretStateKey(key)` identifies if a setting contains sensitive information that must be routed to `context.secrets` [src/core/config/ContextProxy.ts:4-21]().

**Diagram: Storage Layer Routing via ContextProxy**

```mermaid
flowchart TD
    "caller[ClineProvider / webviewMessageHandler]" --> "cp[ContextProxy.setValue]"
    "cp" --> "isk[isSecretStateKey]"
    "isk" -- "true" --> "secrets[context.secrets\nEncrypted Storage]"
    "isk" -- "false" --> "gs[context.globalState\nJSON Storage]"
    "cp" --> "cache[stateCache / secretCache\nIn-memory]"
```

### State Migrations
`ContextProxy` handles complex state migrations during initialization, such as:
- **Image Generation**: Flattening old nested image generation settings [src/core/config/ContextProxy.ts:91-92]().
- **Prompt V2**: Detecting old v1 default condensing prompts using fingerprinting and clearing them so users receive the improved v2 default [src/core/config/ContextProxy.ts:157-181]().
- **Legacy Fields**: Moving `customCondensingPrompt` into the new `customSupportPrompts` structure [src/core/config/ContextProxy.ts:113-143]().

## ProviderSettingsManager

`ProviderSettingsManager` (`src/core/config/ProviderSettingsManager.ts`) manages API configuration profiles. A profile encapsulates provider selection (e.g., Anthropic, OpenRouter) and its associated settings (model ID, API keys).

### Profile Schema
Profiles are stored as a `ProviderProfiles` object, which includes a mapping of mode slugs to specific profile IDs, allowing different AI behaviors (Code, Architect, etc.) to use different LLM providers [src/core/config/ProviderSettingsManager.ts:39-55]().

```typescript
// packages/types/src/provider-settings.ts
export type ProviderProfiles = {
    currentApiConfigName: string;
    apiConfigs: Record<string, ProviderSettingsWithId>;
    modeApiConfigs?: Record<string, string>; // Maps mode slug -> config ID
}
```

### Concurrency and Locking
To prevent data corruption during simultaneous writes (e.g., updating settings while switching modes), the manager implements a promise-based sequential lock [src/core/config/ProviderSettingsManager.ts:92-97]().

**Diagram: ProviderSettingsManager Lifecycle**

## Multi-Layer Task Persistence

Roo Code separates task data into three distinct files per task to optimize for performance and context window management. These files are stored in `globalStorageUri/tasks/{taskId}/`.

| File Name | Entity | Purpose |
|---|---|---|
| `api_conversation_history.json` | `ApiMessage[]` | Raw messages sent to/from the LLM, including tool results and thinking [src/core/task-persistence/apiMessages.ts:12-38](). |
| `ui_messages.json` | `ClineMessage[]` | Messages rendered in the React webview, including status "says" and user "asks" [src/core/task-persistence/taskMessages.ts:17-56](). |
| `task_metadata.json` | `TaskMetadata` | Tracks file states (active, stale, user-edited) to detect out-of-band changes [src/core/context-tracking/FileContextTracker.ts:114-138](). |

### Context Tracking System
The `FileContextTracker` uses `vscode.FileSystemWatcher` to monitor files Roo has interacted with. If a user modifies a file externally, the tracker marks the file as "stale" in `task_metadata.json`. Roo then re-reads the file before the next edit to prevent diff application failures [src/core/context-tracking/FileContextTracker.ts:23-77]().

## Model and Endpoint Caching

To minimize latency and API calls, Roo Code implements tiered caching for provider metadata.

1. **Model Cache**: Stores lists of available models for providers like OpenRouter or Ollama. Uses `NodeCache` for memory and JSON files for disk persistence.
2. **Endpoint Cache**: Specifically for OpenRouter, `modelEndpointCache.ts` stores the mapping of model IDs to their specific API endpoints [src/api/providers/fetchers/modelEndpointCache.ts:18-44]().

**Diagram: Tiered Cache Retrieval**

```mermaid

```

## Import and Export System

The `importExport.ts` utility allows users to migrate their entire configuration. It performs "lenient parsing," which sanitizes imported data by removing invalid or retired providers while preserving the rest of the profile [src/core/config/importExport.ts:44-63]().

- **Sanitization**: Checks `apiProvider` against `isProviderName` to ensure compatibility [src/core/config/importExport.ts:52-60]().
- **Atomic Import**: Updates `ProviderSettingsManager`, `ContextProxy`, and `CustomModesManager` in a coordinated sequence to ensure state consistency [src/core/config/importExport.ts:156-185]().
