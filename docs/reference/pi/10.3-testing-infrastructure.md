The `pi` monorepo employs a comprehensive testing infrastructure designed to ensure robustness across its modular packages. This infrastructure includes granular unit tests, integration and regression suites, behavioral evals, session repository and execution environment conformance suites, benchmarks, and end-to-end (E2E) tests interacting with live Large Language Model (LLM) providers or deterministic faux providers.

---

## Test Suite Organization

### Core Test Tools and Scripts

- **Vitest** serves as the primary test runner across the monorepo due to its compatibility with ESM and TypeScript, as well as its speed and feature set. It runs tests ranging from unit to behavioral evals [packages/evals/package.json:6-12]().

- **`pi-test.sh`**: A custom script harnessing the `coding-agent` CLI to run scripted agent sessions as test cases. It supports the `--no-env` option to clear environment variables, enabling clean offline/local testing with no dependency on user API keys.

- **`test.sh`**: The root-level orchestrator shell script that sequentially or concurrently runs all package test suites while safeguarding user local configurations by backing them up and restoring after tests.

- **CI Integration**: The `.github/workflows/ci.yml` file automates continuous integration tasks, including dependency installation, build, linting, type-checking, and execution of tests across the monorepo to maintain code health [`.github/workflows/ci.yml:1-66`]().

### Test Categories and Locations

| Category                     | Location                                                        | Focus                                                                                     |
| ---------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **Unit Tests**               | `packages/*/src/**/*.test.ts`                                  | Tests for functions, classes, and utilities                                               |
| **Integration & Regression**| `packages/coding-agent/test/suite/`                            | AgentSession lifecycle, queueing, persistence, regressions                                |
| **Provider E2E Tests**       | `packages/ai/test/`                                            | Live provider interaction tests covering streaming, tool calls, and edge scenarios       |
| **Storage Conformance**      | `packages/durable/src/testing/storage-conformance.ts`          | Conformance tests across JSONL, memory, and SQLite storage backends                       |
| **Environment Conformance**  | `packages/durable/src/testing/env-conformance.ts`              | Conformance tests across `ExecutionEnv` implementations (`NodeExecutionEnv`, remote envs) |
| **Benchmarks**               | `packages/durable/bench/` & `packages/durable/test/`           | Performance benchmarking for session storage implementations                              |
| **Behavioral Evals**         | `packages/evals/src/`                                          | Agent workflow correctness tests using the `vitest-evals` behavioral framework           |

## Agent-Session Test Harnesses

The `AgentSession` class, crucial to pi’s agent interaction lifecycle, is tested via harnesses primarily in `packages/coding-agent/test/test-harness.ts`. These harnesses simulate scripted agent conversations deterministically using a mock "faux" AI provider.

### Harness Architecture and Workflow

- **`createTestHarness()`** function initializes an isolated temporary directory environment, registers a faux AI provider, and sets up in-memory session managers, settings managers, and auth storage. It then creates an `AgentSession` instance to run scripted conversations in isolation [packages/coding-agent/test/test-harness.ts:100-189]().

- **`registerFauxProvider()`** installs a mock LLM provider that returns scripted response steps. This enables tests to simulate multi-turn streams with fixed or factory-generated response sequences. These scripted sequences contain assistant texts, tool call events, and control signals [packages/coding-agent/test/test-harness.ts:34-92]().

- The harness interface exposes utilities:
  - `faux.setResponses(...)` to load scripted provider responses.
  - `getUserTexts()` and `getAssistantTexts()` for easy access to the dialogue history.
  - Subscriptions to fine-grained session events with filtering support.

## LLM Provider End-to-End (E2E) Tests

The AI abstraction in `@earendil-works/pi-ai` is covered by exhaustive E2E tests that verify streaming correctness, token accounting, context overflow detection, and tool call behaviors across multiple providers.

### Key E2E Test Suites and Features:

- **`stream.test.ts`**: Core streaming API validations including text generation, tool call lifecycle streaming, and error conditions [packages/ai/test/stream.test.ts:1-174]().

- **`total-tokens.test.ts`**: Ensures token usage counters (input, output, cache) correctly sum to total tokens reported [packages/ai/test/total-tokens.test.ts:1-120]().

- **`cross-provider-handoff.test.ts`**: Tests seamless provider/model handoff in sessions, validating tool call ID adjustments and reasoning block handoffs.

- **`image-tool-result.test.ts`**: Verifies correct handling of tool call results containing image content blocks in vision-capable models [packages/ai/test/image-tool-result.test.ts:1-109]().

### Edge Case Scenarios:

- **Context Overflow Detection**: Generating excessively large prompts to trigger overflow and verify proper detection using `isContextOverflow()` [packages/ai/test/context-overflow.test.ts:1-105]().

- **Abort Signal Handling**: Tests generation streams aborted mid-flight still produce usable partial tokens [packages/ai/test/abort.test.ts:1-56](), [packages/ai/test/tokens.test.ts:1-84]().

- **Unicode Surrogate Safety**: Ensures streamed Unicode, including emoji surrogate pairs, are safely handled without broken sequences [packages/ai/test/unicode-surrogate.test.ts:1-120]().

- **Orphaned Tool Call Filtering**: Simulates aborted tool calls to confirm call result consistency [packages/ai/test/tool-call-without-result.test.ts:1-91]().

- **Empty Message Results**: Validates handling of empty or whitespace-only assistant messages [packages/ai/test/empty.test.ts:1-43]().

## Storage and Environment Conformance Suites

The durable session storage backends and execution environments undergo rigorous conformance tests to validate correctness in lifecycles, mutations, persistence, file operations, and forking behavior.

### Framework and Implementation

- The storage conformance suites live primarily at `packages/durable/src/testing/storage-conformance.ts`. They require a `StorageConformanceOptions` object with a `withStorage` factory to instantiate the storage under test, and assertion utilities [packages/durable/src/testing/types.ts:1-18](). They systematically test atomic commit behavior, rollback correctness, and message branch mutation sequencing across in-memory, JSONL file storage, and SQLite-backed storage [packages/durable/src/testing/storage-conformance.ts:91-181]().

- Environment abstraction conformance tests for the `ExecutionEnv` interface reside in `packages/durable/src/testing/env-conformance.ts`. They verify file reading, writing, watching (`NodeFileWatcher`), path resolution, and error codes for diverse implementations including `NodeExecutionEnv` [packages/durable/src/testing/env-conformance.ts:1-168](), [packages/durable/src/env/node.ts:1-50]().

## Benchmarks (`packages/durable/bench` and `packages/durable/test`)

The monorepo includes dedicated benchmarks measuring performance and memory usage for core durable session storages and tool output handling.

### Benchmark Descriptions

1. **Storage Benchmarks (`bench:storage`)** measure throughput and allocation over various backends and dataset sizes, especially in-memory storage optimized benchmarks run with:

   ```bash
   npm run bench:storage:memory
   ```
   which executes `node --conditions=source --experimental-strip-types test/storage-memory.ts` [packages/durable/package.json:122-133]().

2. **Tool Output Benchmarks (`bench:tool-output`)** focus on tool output processing performance, measured with:

   ```bash
   npm run bench:tool-output
   ```
   that runs under Node with exposed GC flags to measure memory [packages/durable/package.json:122-133]().

## Behavioral Eval Framework (`packages/evals`)

The `evals` package implements a behavioral evaluation framework running simulated and live agent session workflows against models, scoring outputs via the `vitest-evals` behavioral testing suite.

### Architecture and Usage

- Evals are initiated through the `eval` npm script, which runs host and docs eval suites to validate agent workflow correctness [packages/evals/package.json:6-12]():

  ```bash
  PI_PROVIDER=openai-codex PI_MODEL=gpt-5.6-sol npm run eval -w packages/evals
  ```

- Host evals run via `vitest run --config vitest.evals.config.ts --project host`.

- Docs evals (`*.docs.eval.ts`) run isolated test arms to compare agent completions with and without supplied documentation context.

- The core harness for eval runs is created by `createPiDocumentationEvalHarness()` which sets up workspace and service directories alongside fresh `AgentSession` instances [packages/evals/src/harness.ts:1-110]().

- The scoring harness converts agent outputs to structured data and applies the `StructuredOutputJudge` for correctness.

## Session Lifecycle, Compaction, and Regression Tests

The testing infrastructure contains focused tests for complex `AgentSession` features, particularly around session state compaction, retry logic, and queue management, ensuring stable behavior under load and recovery conditions.

### Auto-Compaction Queue Tests

- Validate `AgentSession` compaction triggered by token threshold or overflow with queued messages.

- Confirm that compaction triggers correctly, avoids repeated retries after overflow recovery attempts, and ignores stale usage data to prevent infinite loops [packages/coding-agent/test/agent-session-auto-compaction-queue.test.ts:59-133]().

### Overflow Recovery and Retry Behavior

- Assert that after a single compact-and-retry recovery attempt, the session signals fatal error and skips further retries to prevent runaway loops [packages/coding-agent/test/agent-session-auto-compaction-queue.test.ts:135-188]().

### Regression Suites

- The regression tests in `packages/coding-agent/test/suite/regressions/` track fixes for prior issues such as prompt replacement, queue replay accuracy, and slash command follow-up execution correctness [packages/coding-agent/test/suite/regressions/2023-queued-slash-command-followup.test.ts:1-50]().
