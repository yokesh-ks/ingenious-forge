## Purpose and Scope
This page details the storage and persistence layer of `@earendil-works/pi-durable` (`packages/durable`), which provides transactional durability for conversations, transcript entries, state machines (tasks), user input submissions, and scoped JSON documents. It covers durable storage types, memory, SQLite (Node.js and Cloudflare Workers), and JSONL implementations, schema management and automatic migrations, session transactions, document semantics, execution timers, wake contracts, test-workers, and storage conformance suites.

## 1. Core Durable Records and Types

The durable persistence model revolves around strongly-typed, immutable records and monotonically increasing sequence numbers (`Seq`) assigned to atomic storage commits.

### Key Code Entities
- `Id<Kind, Type>`: Session-global safe integer identifier branded with nominal typing for specific record kinds (`conversation`, `entry`, `task`, `submission`, `document`) [packages/durable/src/storage/sqlite/storage.ts:1-35]().
- `Seq`: A strictly increasing number assigned to one atomic storage commit [packages/durable/src/storage/sqlite/storage.ts:25]().
- `ConversationRecord`: Immutable conversation metadata containing parent ancestry pointers and task ownership bindings [packages/durable/src/storage/sqlite/storage.ts:9-10]().
- `EntryRecord`: Immutable transcript record representing user messages, assistant outputs, system changes, or reset boundaries [packages/durable/src/storage/sqlite/storage.ts:18-20]().
- `SubmissionRecord`: Tracks host submissions (user input or entry writes) through states like `queued`, `placed`, `done`, or `unanswered` [packages/durable/src/storage/sqlite/storage.ts:29-31]().

## 2. Storage Implementations: Memory, SQLite, and JSONL

The storage layer defines a uniform `Storage` interface implemented across volatile and persistent backends [packages/durable/src/storage/sqlite/storage.ts:152]().

### Memory Storage (`MemoryStorage`)
`MemoryStorage` retains all tables, documents, and sequences in memory [packages/durable/src/storage/memory.ts:72-92](). It provides complete transactional isolation, cursor-based pagination, and fork-aware scans, serving as the primary storage engine for unit tests and ephemeral harnesses [packages/durable/src/storage/memory.ts:126-210]().

### SQLite Storage (`SqliteStorage`)
The persistent SQLite backend (`SqliteStorage`) implements the storage contract over SQLite databases [packages/durable/src/storage/sqlite/storage.ts:151-185](). It supports native Node.js (`node:sqlite`) via `openNodeSqliteStorage()` [packages/durable/src/storage/sqlite/node.ts:15-22](), and Cloudflare Workers via `openDurableObjectSqliteStorage()` [packages/durable/test-workers/worker.ts:15](). Multiple SQLite adapters can coordinate operations to safely share a single underlying database instance [packages/durable/test/sqlite-cloudflare.test.ts:43-71]().

### JSONL Storage (`JsonlStorage`)
`JsonlStorage` provides a file-system backed log format storing operations as append-only records in `main.jsonl` along with task and document sidecar files (`doc-*.jsonl`, `task-*.jsonl`) [packages/durable/src/storage/jsonl/storage.ts:30-61](). It incorporates corruption detection (`JsonlCorruptionError`) and poison safeguards (`JsonlStoragePoisonedError`) [packages/durable/src/storage/jsonl/storage.ts:82-94]().

## 3. Schema and Migrations

SQLite persistence relies on a structured schema and automated migration runners [packages/durable/src/storage/sqlite/migrations.ts:11-138]().

### Schema Evolution and Version 2 Migration
When opening a SQLite storage instance, `SqliteStorage.open()` automatically checks and applies migrations via `applySqliteMigrationsForSchema()` [packages/durable/src/storage/sqlite/storage.ts:168-175](), [packages/durable/src/storage/sqlite/migrations.ts:132-138](). Opening a database migrates it through version history, rebuilding tables (such as tasks with version 2 adding the `sleeping` task status) to support advanced crash-loop guards, sleeping task states, and task graphs [packages/durable/src/storage/sqlite/migrations.ts:91-112](). Prefixes can be configured to namespace all tables and indices within shared databases [packages/durable/src/storage/sqlite/storage.ts:64-70](), [packages/durable/test/sqlite-cloudflare.test.ts:22-41]().

## 4. Session Transactions, Documents, and Entries

### Session Persistence and Transactions
The storage `commit()` method processes atomic batches of writes (`StorageWrite[]`) within database transactions [packages/durable/src/storage/sqlite/storage.ts:187-192](), [packages/durable/src/storage/memory.ts:1-35](). Every atomic commit guarantees that all record writes, task state updates, and Chord-tracked document deltas succeed together or roll back entirely [packages/durable/src/storage/sqlite/storage.ts:191-192]().

### Typed Documents and Entries
- **Documents:** Typed JSON state managed via scopes (`session`, `conversation`, `task`) supporting history modes, delta revisions, and retirement [packages/durable/src/storage/sqlite/storage.ts:53-62,101-130]().
- **Entries:** Immutable transcript records stored with associated commit sequences (`commitSeq`) [packages/durable/src/storage/sqlite/storage.ts:44]().

Sources: [packages/durable/src/storage/sqlite/storage.ts:40-192](), [packages/durable/src/storage/memory.ts:41-65]()

## 5. Timers, Wake Contracts, and Test-Workers

The durable harness coordinates background work, idle-memory eviction, and durable sleeping tasks through a pluggable timer and wake architecture [packages/durable/src/timers.ts:39-78]().

### Key Concepts
- **Timers:** `nativeTimer` handles timeouts, pacing delays beyond `setTimeout` limits in step increments, and marking background timers as unreferenced (`unref()`) [packages/durable/src/timers.ts:17-36](). `hostTimers` wraps host-provided timers with fallbacks [packages/durable/src/timers.ts:51-78]().
- **Wake Contracts (`onWake`):** Host environments receive wake notifications when sessions require processing. In Cloudflare Durable Objects, alarms wake the object to call `resume()` [packages/durable/test-workers/worker.ts:102-114]().
- **Test-Workers:** Dedicated test workers (`packages/durable/test-workers/worker.ts`) validate Cloudflare Worker integration, alarms, and scripted multi-step responses under simulated conditions [packages/durable/test-workers/worker.ts:39-151]().

Sources: [packages/durable/src/timers.ts:1-78](), [packages/durable/test-workers/worker.ts:1-151]()

## 6. Storage Conformance Suites

To ensure backend interchangeability between `MemoryStorage` and `SqliteStorage`, `packages/durable` provides comprehensive storage conformance test suites [packages/durable/src/testing/storage-conformance.ts:134-1813]().

The conformance suite validates:
- Atomic commit serialization, primary key generation, and root conversation preservation (`ROOT_CONVERSATION_ID`) [packages/durable/src/testing/storage-conformance.ts:137-144]().
- Adoption contract guarantees where `adopt()` runs exactly once per committed batch before resolution [packages/durable/src/testing/storage-conformance.ts:99-185]().
- Cursor pagination and range scanning for entries, tasks, submissions, and conversations [packages/durable/src/testing/storage-conformance.ts:1-1813]().
- Scoped document creation, delta updates, branching/forking history, and retirement semantics [packages/durable/src/testing/storage-conformance.ts:1-1813]().

Sources: [packages/durable/src/testing/storage-conformance.ts:1-1813](), [packages/durable/test/sqlite-storage.test.ts:120-122]()
