## Purpose and Scope

This page covers the prompt management infrastructure in OpenClaude, detailing how system prompts are assembled, cached, and parameterized. It explores prompt identity enforcement, built-in agent system prompts (such as exploration and planning agents), persistent memory and conversation arc injection, and specialized instructions like output styles and coding guidelines.

---

## 1. Prompt Constants & System Prompt Architecture

System prompts in OpenClaude are constructed dynamically from modular sections combined with static foundational instructions. To optimize API performance through provider-side prompt caching (such as Anthropic's prompt caching), OpenClaude separates static cross-organizational instructions from session-specific metadata using a strict boundary marker.

The global boundary marker `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` separates cacheable prefix sections from dynamic user or session-specific content [src/constants/prompts.ts:105-116](). Everything before this marker can be safely cached at the provider level with a `global` scope, while everything after it adapts to runtime states, memory persistence, and environment settings.

## 2. Prompt Identity & Branding

OpenClaude maintains strict branding boundaries to ensure prompts refer to OpenClaude rather than upstream Claude Code distributions. The prompt identity system replaces official CLI references with OpenClaude descriptors across all execution modes [src/constants/promptIdentity.test.ts:80-116]().

Identity resolution checks environment overrides such as `CLAUDE_CODE_SIMPLE` (bare mode) [src/constants/promptIdentity.test.ts:92-100]() and updates model identities dynamically mid-session when models are switched [src/constants/promptIdentity.test.ts:102-115](). Package versions, issues explainers, and display tags are injected at build time or via test-time mock macros [src/constants/promptIdentity.test.ts:29-39]().

Sources: `[src/constants/promptIdentity.test.ts:1-168]()`

## 3. Built-In Agent Prompts

Sub-agents and specialized built-in agents execute with isolated, purpose-built system prompts. These prompts enforce strict operating boundaries (such as read-only access) and optimize the agent for specific token-efficiency or speed profiles.

### Explore Agent (`EXPLORE_AGENT`)
The explore agent is specialized for rapid codebase navigation and regex text searching [src/tools/AgentTool/built-in/exploreAgent.ts:13-57](). It operates under a strict read-only constraint that explicitly prohibits creating, modifying, or deleting files [src/tools/AgentTool/built-in/exploreAgent.ts:26-37](). It defaults to a fast model tier (`haiku`) and omits `CLAUDE.md` context loading to maximize response speed [src/tools/AgentTool/built-in/exploreAgent.ts:77-80]().

Sources: `[src/tools/AgentTool/built-in/exploreAgent.ts:13-80]()`

### Plan Agent (`PLAN_AGENT`)
The plan agent functions as a software architect, exploring codebases to design implementation steps without altering system state [src/tools/AgentTool/built-in/planAgent.ts:21-34](). Its prompt mandates an explicit output format containing a list of critical implementation files [src/tools/AgentTool/built-in/planAgent.ts:60-70]().

Sources: `[src/tools/AgentTool/built-in/planAgent.ts:21-70]()`

### General Purpose Agent (`GENERAL_PURPOSE_AGENT`)
The general purpose agent handles multi-step research and cross-file analysis [src/tools/AgentTool/built-in/generalPurposeAgent.ts:5-16](). It has access to the full tool registry (`*`) but is instructed to prefer editing existing files over creating new ones [src/tools/AgentTool/built-in/generalPurposeAgent.ts:15-16]().

Sources: `[src/tools/AgentTool/built-in/generalPurposeAgent.ts:5-16]()`

## 4. Memory, Conversation Arcs & Context Injection

Persistent memory structures and conversation arcs are appended dynamically to the model system prompt during query execution [src/query.conversationArc.test.ts:112-169](). 

The memory subsystem is governed by `isAutoMemoryEnabled()`, which evaluates environment variables (`CLAUDE_CODE_DISABLE_AUTO_MEMORY`, `CLAUDE_CODE_SIMPLE`), remote connection state, and raw per-source settings from `settings.json` (`memory.autoWrite` and `autoMemoryEnabled`) [src/memdir/paths.ts:31-91](). When active, retrieved memories and conversation goals are wrapped in data-only markers (such as `BEGIN RETRIEVED MEMORY (DATA ONLY)`) to prevent prompt injection while preserving cross-turn context [src/query.conversationArc.test.ts:159-162]().

Sources: `[src/memdir/paths.ts:31-91]()`, `[src/query.conversationArc.test.ts:112-169]()`

## 5. Output Styles & Specialized Guidance

System prompts incorporate task-specific behavior directives validated by dedicated test suites:
- **Timing and Wiring Robustness:** Coding system prompts instruct the model to derive timing-sensitive logic (such as animations or physics timers) from actual elapsed time and ensure all introduced elements are fully wired up [src/constants/prompts.doingTasks.test.ts:23-35]().
- **Immediate Tool Execution:** Prompts instruct the model to invoke tools immediately when planning to analyze files or complete tasks, preventing redundant explanatory responses that wait for secondary user prompts [src/constants/promptIdentity.test.ts:117-162]().
- **Language Preferences:** Dynamic language sections adapt explanations and communications to user-specified language preferences while keeping code identifiers and technical terms in their original form [src/constants/prompts.ts:136-143]().
