OpenClaude manages multi-provider authentication through a unified credential subsystem supporting Anthropic API keys, standard OAuth tokens, GitHub device-flow tokens, xAI loopback OAuth callbacks, secure storage backends (macOS Keychain, encrypted files, process environment overrides), and dynamic auth routing.

---

## 1. OAuth Flows & Third-Party Authentication

Third-party providers require specialized authentication protocols beyond standard API keys. OpenClaude implements dedicated flows for GitHub Copilot / Models, xAI, and Anthropic Console/Claude AI OAuth.

### GitHub Device Flow & Token Lifecycle
GitHub authentication relies on the OAuth Device Authorization Grant (`src/services/github/deviceFlow.ts`), allowing headless or terminal-based sign-in. The process follows these stages:
1. **Device Code Request**: The CLI requests a user code and verification URI from GitHub (`requestDeviceCode`) [src/commands/onboard-github/onboard-github.tsx:9-13]().
2. **User Authorization**: The user visits `https://github.com/login/device` and enters the code.
3. **Polling**: The CLI polls GitHub's token endpoint (`pollAccessToken`) [src/commands/onboard-github/onboard-github.tsx:9-13]() until the user completes verification.
4. **Exchange for Copilot Token**: The acquired OAuth token is exchanged for a GitHub Copilot bearer credential (`exchangeForCopilotToken`) [src/utils/githubModelsCredentials.ts:3]().
5. **Hydration & Persistence**: Tokens are written to secure storage and optionally hydrated into session environment variables (`hydrateGithubModelsTokenFromSecureStorage`) [src/utils/githubModelsCredentials.ts:88-121]().

### xAI OAuth Loopback Server
For xAI authentication, OpenClaude starts a temporary local HTTP loopback server (`startXaiOAuthCallback`) [src/services/api/xaiOAuthCallback.ts:89-96]() that handles CORS preflights (`OPTIONS`) and private network access headers (`Access-Control-Allow-Private-Network: true`) to support direct browser-to-loopback token pushes from `auth.x.ai` and `accounts.x.ai` [src/services/api/xaiOAuthCallback.ts:79-87]().

## 2. Auth Routing & Credential Resolution

OpenClaude decides whether to use first-party Anthropic OAuth, third-party vendor flags, or external environment keys via inspection functions in `src/utils/auth.ts`.

### Key Resolution Functions
* `isAnthropicAuthEnabled()`: Evaluates environment overrides (`--bare`, `ANTHROPIC_UNIX_SOCKET`, 3P provider flags like `CLAUDE_CODE_USE_GITHUB`) to determine if Anthropic credentials should be sent [src/utils/auth.ts:102-163]().
* `getAuthTokenSource()`: Discovers the active token source, prioritizing `apiKeyHelper`, environment variables, file descriptors, or secure storage backends [src/utils/auth.ts:167-178]().
* `isManagedOAuthContext()`: Detects if running inside Claude Desktop, SSH auth proxy, or remote execution environments where local API key configuration must be bypassed [src/utils/auth.ts:91-98]().

## 3. Secure Storage Backends & Provider Secrets

OpenClaude abstracts platform-specific secure storage (macOS Keychain, Linux Secret Service, Windows Credential Manager) through a unified storage interface (`src/utils/secureStorage/index.ts`).

### Credential Blob Storage Schema
Secrets are stored in JSON blobs within secure storage. For instance, GitHub Models credentials conform to `GithubModelsCredentialBlob`:
```typescript
export type GithubModelsCredentialBlob = {
  accessToken: string
  oauthAccessToken?: string
  credentialType?: 'copilot_token' | 'copilot_key'
}
```
*[src/utils/githubModelsCredentials.ts:11-15]*, stored under the key `githubModels` *[src/utils/githubModelsCredentials.ts:7]*

### Environment Hydration & Clearing
To bridge secure storage tokens into runtime API clients (like the OpenAI shim and Codex transport), OpenClaude hydrates stored tokens into process environment variables prior to request execution:
* `hydrateGithubModelsTokenFromSecureStorage()`: Copies stored GitHub/Copilot tokens into `GITHUB_TOKEN` or `GITHUB_COPILOT_KEY` *[src/utils/githubModelsCredentials.ts:88-121].*
* `clearHydratedGithubModelsTokenFromEnv()`: Cleans up session environment variables upon de-authentication or profile switching *[src/utils/githubModelsCredentials.ts:134-155].*
