## Purpose and Scope

The Integrations Registry acts as the unified configuration and metadata backbone for OpenClaude's multi-provider architecture. It defines how the system discovers, validates, and routes requests across hundreds of upstream vendors, aggregating gateways, hardware providers, and custom model endpoints. 

This page provides a high-level overview of the registry design, descriptor types, generated static manifests, and route metadata management. For low-level discovery mechanics, caching policies, and specific gateway integration details, refer to the child pages:
- [Model Discovery & Caching](#3.2.1) — Covers `discoveryService`, `discoveryCache`, live `/v1/models` endpoint probing, staleness policies, and hybrid catalog integration.
- [AIMLAPI & Specific Gateway Integrations](#3.2.2) — Covers AIMLAPI configuration/top-up flows, OpenCode, NVIDIA NIM, Ollama, OpenRouter, and custom gateway shims.

## 1. Registry Architecture & Descriptors

The OpenClaude integration layer is built around static-first TypeScript descriptors defined in `src/integrations/descriptors.ts` and managed through registry functions in `src/integrations/registry.ts`. Providers are categorized into vendors (direct API providers like Anthropic or Z.AI), gateways (aggregators like OpenRouter, AIMLAPI, or Gitlawb Opengateway), and brands/models.

Gateways and vendors are declared using builder functions such as `defineGateway()` [src/integrations/gateways/gitlawb-opengateway.ts:63-63] which enforce strict structural validation. Descriptors encapsulate authentication modes (`api-key`, `oauth`, `adc`, `token`, `none`), transport configurations (such as OpenAI-compatible shims or native clients), readiness probes, and model catalogs [src/integrations/descriptors.ts:5-152].

## 2. Generated Manifests & Route Metadata

To avoid heavy runtime evaluation of the entire descriptor graph during CLI startup, OpenClaude utilizes build-time generation scripts that output plain-data artifacts [src/integrations/generated/integrationManifest.generated.ts:1-8]. 

The preset manifest maps environment variables (`apiKeyEnvVars`, `baseUrlEnvVars`, `modelEnvVars`), route kinds (`vendor` vs `gateway`), and visual badges. Concurrently, route metadata utilities (`src/integrations/routeMetadata.ts`) inspect base URL patterns and environment markers to resolve active route identifiers [src/integrations/runtimeMetadata.ts:20-27], ensuring clean separation between generic OpenAI-compatible traffic and specialized providers.

## 3. Catalog Entries & Time-Boxed Windows

Model catalogs within descriptors support static, dynamic, and hybrid sourcing models [src/integrations/descriptors.ts:105-141]. Each entry (`ModelCatalogEntry`) defines mapping parameters, capabilities, context windows, and transport-level overrides [src/integrations/descriptors.ts:110-132].

To handle temporary promotional or time-limited models without requiring client-side software updates, the registry supports the `availableUntil` ISO-8601 constraint [src/integrations/descriptors.ts:117-124]. Once the specified timestamp passes, model filters drop the entry from picker options and runtime verification bounds [src/integrations/ling-tiny.test.ts:10-76], preventing the submission of stale or rejected identifiers upstream.
