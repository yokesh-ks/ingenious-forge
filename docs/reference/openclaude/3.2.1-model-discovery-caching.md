## Purpose and Scope
OpenClaude supports over 200 LLM providers, gateways, and local runtimes. Because model catalogs change frequently and custom local endpoints (such as Ollama, LM Studio, or vLLM) expose dynamic model sets, OpenClaude implements a robust **Model Discovery & Caching** subsystem. This subsystem is responsible for probing endpoint model lists (via `/v1/models` or native tags endpoints), maintaining time-boxed disk/memory caches with partition separation, handling staleness, and supporting hybrid catalogs during the API bootstrap phase.

---

## 1. Core Components and Registry Architecture
The discovery layer is divided into two primary modules:
- **`discoveryService`**: Manages network-level model probing against endpoint base URLs, handles authorization header pruning for safe proxy requests, and normalizes disparate provider JSON payloads into uniform model descriptors (`[src/integrations/discoveryService.test.ts:122-144]()`).
- **`discoveryCache`**: Provides persistent caching for discovered models, storing them with timestamps, validation metadata, and endpoint base URL partitioning to prevent cross-contamination between distinct local or remote deployments (`[src/integrations/discoveryService.test.ts:180-183]()`).

## 2. `/v1/models` Probing and Endpoint Resolution
When interacting with OpenAI-compatible gateways or local runtimes, `discoveryService` sends an HTTP `GET` request to the target `/v1/models` route. 
- For local instances like Ollama, it falls back or cross-probes native endpoints to extract quantization levels, family tags, and parameter sizes (`[src/utils/providerDiscovery.ts:75-109]()`).
- **Security & Authorization Hygiene**: When routing through generic proxy configurations or hybrid gateways (e.g., ApiSmart or OpenRouter), credential isolation is enforced. For instance, `discoveryService` ensures that specific vendor API keys are not leaked to overridden discovery URLs if the base URL points to an unverified proxy `[src/integrations/discoveryService.test.ts:122-144]()`.
- **Endpoint Partitioning**: Caches are strictly partitioned by the endpoint base URL. If a user switches between local test endpoints (e.g., `http://127.0.0.1:1337/v1` and `http://localhost:11434`), discovery entries remain isolated `[src/integrations/discoveryService.test.ts:180-183]()`.

## 3. Staleness, Expiration, and Hybrid Catalogs
To avoid blocking startup or query execution on slow network probes, discovered model lists rely on a cache layer with defined staleness rules:
- **Time-Boxed Entries**: Cached model lists include generation timestamps. If the cache age exceeds the staleness threshold checked via `isCacheStale` (`[src/commands/model/model.tsx:10-14]()`), OpenClaude performs a background refresh while optionally falling back to stale cached results to maintain zero-latency responsiveness.
- **Hybrid Catalogs**: OpenClaude merges static built-in descriptors (defining known model context windows, capability routes, and pricing metadata) with dynamically discovered models from the live `/v1/models` payload. Discovered models that lack explicit static metadata inherit safe fallback context windows (`OPENAI_FALLBACK_CONTEXT_WINDOW` set to 128k tokens by default) to prevent auto-compact floor paradoxes (`[src/utils/context.ts:19-27]()`).

## 4. API Bootstrap Sequence
During CLI startup (`[src/services/api/bootstrap.ts]()`), the API bootstrap coordinator initializes the provider state, validates required credentials, and triggers model resolution:
1. **Profile Loading**: Reads active profile settings and environment overrides (`.openclaude-profile.json`).
2. **Catalog Hydration**: Ensures the integration registry is loaded (`[src/integrations/runtimeMetadata.ts:14-19]()`) and queries `discoveryService` if live validation is required for dynamic providers (like OpenRouter or OpenGateway).
3. **Runtime Limit Resolution**: Evaluates model context windows using the authoritative precedence chain managed in `resolveModelRuntimeLimits` (`[src/integrations/runtimeMetadata.ts:11-13]()`): exact environment overrides (`CLAUDE_CODE_OPENAI_CONTEXT_WINDOWS`), built-in catalogs, prefix environment matches, `settings.json` `modelLimits`, the discovery cache, and finally default descriptors (`[src/utils/model/openaiContextWindows.ts:11-15]()`).
