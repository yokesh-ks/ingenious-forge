## Purpose and Scope

This page details the build orchestration, bundling configuration, external dependency mapping, compile-time module stubbing, verification suites, and executable launcher mechanisms for OpenClaude as defined in `scripts/build.ts` [scripts/build.ts:1-136](), `scripts/externals.ts` [scripts/externals.ts:1-147](), `scripts/no-telemetry-plugin.ts` [scripts/no-telemetry-plugin.ts:1-140](), and `package.json` [package.json:28-83]().

## 1. Core Build Orchestration (`scripts/build.ts`)

The build pipeline centers on `scripts/build.ts`, which leverages Bun's native bundler to compile TypeScript source code into standalone distributable JavaScript bundles (`dist/cli.mjs` and `dist/sdk.mjs`) [scripts/build.ts:2-9](). 

The build script manages production React optimization by replacing development builds with production shims using `productionReactPlugin`, mapping packages like `react`, `react-reconciler`, and `scheduler` to their compiled production CommonJS counterparts [scripts/build.ts:26-79](). It also compiles a static manifest of `featureFlags` that govern compile-time feature inclusion (such as `CONTEXT_COLLAPSE`, `BG_SESSIONS`, and `ULTRATHINK`) [scripts/build.ts:84-136]().

## 2. Dependency Bundling & Externalization (`scripts/externals.ts`)

OpenClaude splits dependencies into bundled utilities and external runtimes via `scripts/externals.ts` [scripts/externals.ts:1-147](). 

`COMMON_EXTERNALS` defines packages that must never be inlined into bundles due to native compilation requirements, absolute path resolution dependencies (like WebAssembly files or CLI binaries), or optional cloud integrations [scripts/externals.ts:15-47](). `SDK_ONLY_EXTERNALS` marks UI and framework dependencies (such as `react` and `react-reconciler`) as external specifically for SDK compilation targets [scripts/externals.ts:50-55]().

| External Category | Representative Packages | Rationale |
| :--- | :--- | :--- |
| `COMMON_EXTERNALS` | `sharp`, `@vscode/ripgrep`, `web-tree-sitter`, `@aws-sdk/*` | Native binaries, WASM constraints, or heavy cloud SDKs. |
| `SDK_ONLY_EXTERNALS` | `react`, `react-reconciler`, `@anthropic-ai/sdk` | React reconcilers and framework bindings kept external for SDK consumers. |
| `OPTIONAL_RUNTIME_EXTERNALS` | `@anthropic-ai/bedrock-sdk`, `google-auth-library` | Dynamically required on demand to maintain lightweight default installs. |
| `INTENTIONALLY_BUNDLED` | `commander`, `chalk`, `zod`, `ora` | Lightweight utility libraries safe for static inlining. |

## 3. Telemetry Removal & Compile-Time Stubs (`scripts/no-telemetry-plugin.ts`)

The `noTelemetryPlugin` inside `scripts/no-telemetry-plugin.ts` acts as a build-time security and privacy enforcement mechanism [scripts/no-telemetry-plugin.ts:123-140](). It intercepts module resolution requests for analytics, telemetry, auto-updater ping mechanisms, and internal employee logging services, replacing them with lightweight no-op stubs [scripts/no-telemetry-plugin.ts:1-122]().

Key modules intercepted and stubbed by `noTelemetryPlugin` include:
* `utils/autoUpdater`: Replaces version checking and GCS/npm auto-update calls with safe no-op defaults [scripts/no-telemetry-plugin.ts:27-40]().
* `utils/plugins/fetchTelemetry`: Neutralizes plugin download telemetry reporting [scripts/no-telemetry-plugin.ts:44-47]().
* `services/internalLogging`: Stubs employee-specific debugging hooks and container identification [scripts/no-telemetry-plugin.ts:57-60]().
* Protobuf event definitions (`types/generated/...`): Replaces internal event loggers with pass-through identity serializers [scripts/no-telemetry-plugin.ts:80-114]().

## 4. Runtime Launcher, Heap Management & Compile Cache

The execution entrypoints defined in `package.json` [package.json:28-83]() orchestrate startup through wrapper scripts that manage V8 heap limits, compile caching, and execution of built distribution bundles (`dist/cli.mjs`) [package.json:6-15]().

### Key Execution Phases:
1. **Heap Guard**: Relaunches process execution with appropriate V8 heap allocations and `--expose-gc` flags for long-running assistant sessions.
2. **Compile Cache**: Activates Node module compile-cache support where available to accelerate cold starts.
3. **Bundle Execution**: Loads the bundled distribution artifact [package.json:11]().

## 5. Distribution Verification & Phone-Home Guards

To ensure distribution integrity and guarantee zero unauthorized telemetry, the repository maintains verification scripts such as `scripts/verify-clean-install.ts` [package.json:73-75]().

These verification suites pack or download distributable tarballs, simulate cold global installs and upgrades within isolated temporary environments, and enforce strict output whitelisting to catch unexpected warnings, deprecation notices, or unexpected build-artifact inflation [package.json:72-74]().
