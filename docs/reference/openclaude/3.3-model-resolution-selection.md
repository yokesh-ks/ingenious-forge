## Purpose and Scope
This page documents the model resolution and selection subsystem in OpenClaude. It covers how user intents, environment variables, command-line flags, and saved configuration settings are resolved into canonical model identifiers via `getUserSpecifiedModelSetting()` and session handlers. It also details model aliases, provider mappings in configuration tables, options generation, the interactive `ModelPicker` terminal component, cross-profile switching mechanisms, reasoning effort configurations, and token pricing/cost calculation logic.

---

## 1. Model Resolution Hierarchy & Engine (`getUserSpecifiedModelSetting`)

OpenClaude determines the active model for the main execution loop by evaluating multiple configuration sources in a strict priority order. The resolution engine checks runtime overrides, command-line flags, environment variables, and user settings files.

### Resolution Priority Order
1. **Session Override (`/model` command)**: Highest priority, managed via `getMainLoopModelOverride()` [src/utils/model/model.ts:158]().
2. **Startup Flag (`--model`)**: Provided during CLI boot via initial configuration state.
3. **Environment Variables**: Provider-specific or generic model environment variables (e.g., `ANTHROPIC_MODEL`, `OPENAI_MODEL`, `GEMINI_MODEL`).
4. **Saved Settings**: User-configured default model stored in persistent settings files (`settings.model`) [src/utils/model/model.ts:160-161]().

## 2. Aliases, Canonical Names, and Provider Defaults

Model names can be specified as short aliases (e.g., `opus`, `sonnet`, `haiku`) or canonical vendor identifiers. The mapping between architectural tiers and concrete model strings across various LLM providers (First-Party Anthropic, Bedrock, Vertex, OpenAI, Gemini, Mistral, GitHub Copilot, Codex, NVIDIA NIM, MiniMax, Xiaomi MiMo, xAI) is defined in provider-specific configuration tables.

### Small/Fast Model Resolution
For tasks requiring low latency, `getSmallFastModel()` [src/utils/model/model.ts:85-130]() inspects the active API provider (`getAPIProvider()`) and assigns an appropriate lightweight model:
- **Gemini**: `gemini-2.0-flash-lite` [src/utils/model/model.ts:92]()
- **OpenAI**: `gpt-4o-mini` [src/utils/model/model.ts:99]()
- **Codex**: `codexspark` [src/utils/model/model.ts:104]()
- **GitHub Copilot**: `github:copilot` [src/utils/model/model.ts:108]()
- **NVIDIA NIM**: `meta/llama-3.1-8b-instruct` [src/utils/model/model.ts:113]()
- **MiniMax**: `MiniMax-M2.5-highspeed` [src/utils/model/model.ts:118]()

## 3. Model Options, `ModelPicker` & Cross-Profile Switching

The interactive terminal interface exposes model selection through the `ModelPicker` React component (`src/components/ModelPicker.tsx`). 

### `ModelOption` Structure
Each entry in the picker is represented by a `ModelOption` object containing its internal value, display label, description, and an optional cross-profile activation marker [src/utils/model/modelOptions.ts:59-74]():

```typescript
export type ModelOption = {
  value: ModelSetting
  label: string
  description: string
  descriptionForModel?: string
  switchToProfileId?: string
}
```

### Cross-Profile Switching (`__switch_profile__:`)
When users switch models across different provider profiles, `ModelPicker` encodes the target profile ID directly into the option value string using a special prefix [src/utils/model/modelOptions.ts:76-89](). `parseSwitchProfileValue` parses this token into profile ID and model components [src/utils/model/modelOptions.ts:90-105]().

## 4. Effort Levels & Reasoning Control

For models supporting reasoning effort configuration (such as advanced Claude reasoning tiers or OpenAI/Codex reasoning effort parameters), the `EffortPicker` component (`src/components/EffortPicker.tsx`) allows users to adjust inference depth.

### Effort Mapping
- Supported levels include `auto`, `low`, `medium`, `high`, and `max` (normalized to `xhigh` internally for persistence) [src/components/EffortPicker.tsx:47-71]().
- `modelSupportsEffort(model)` verifies whether the active model accepts reasoning parameter payloads [src/components/EffortPicker.tsx:99]().
- Selection updates application state (`effortValue`) and normalizes OpenAI-shaped effort values before persisting to user settings [src/components/EffortPicker.tsx:73-93]().
Sources: `[src/components/EffortPicker.tsx:35-146]()`

## 5. Token Cost & Pricing Engine (`modelCost.ts`)

OpenClaude calculates token usage costs dynamically using model-specific rate structures defined in `src/utils/modelCost.ts`.

### `ModelCosts` Definition
Pricing is tracked per million tokens (Mtok) across input, output, prompt caching write/read operations, and web search requests [src/utils/modelCost.ts:29-35]():

```typescript
export type ModelCosts = {
  inputTokens: number
  outputTokens: number
  promptCacheWriteTokens: number
  promptCacheReadTokens: number
  webSearchRequests: number
}
```

### Cost Calculation & Known Models
The function `getKnownModelCosts()` resolves pricing tiers by matching canonical model names or fallback pricing overrides (`getModelPricingOverride`) [src/utils/modelCost.ts:150-186](). If an unknown model is encountered, it falls back to a default cost structure (`DEFAULT_UNKNOWN_MODEL_COST`) and triggers unknown cost tracking flags [src/utils/modelCost.ts:91]().

```typescript
function tokensToUSDCost(modelCosts: ModelCosts, usage: Usage): number {
  return (
    (usage.input_tokens / 1_000_000) * modelCosts.inputTokens +
    (usage.output_tokens / 1_000_000) * modelCosts.outputTokens +
    ((usage.cache_read_input_tokens ?? 0) / 1_000_000) *
      modelCosts.promptCacheReadTokens +
    ((usage.cache_creation_input_tokens ?? 0) / 1_000_000) *
      modelCosts.promptCacheWriteTokens +
    (usage.server_tool_use?.web_search_requests ?? 0) *
      modelCosts.webSearchRequests
  )
}
```
