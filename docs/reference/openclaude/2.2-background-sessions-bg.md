The background session subsystem enables OpenClaude CLI tasks to execute asynchronously as detached background processes. Users can inspect running tasks, tail their output logs, attach to live sessions, or terminate process trees without blocking the primary terminal shell. 

This document covers the implementation details of the background session registry, process markers, the lifecycle finalizer, terminal facts generation, the background cleanup worker, and the CLI management handlers (`ps`, `logs`, `attach`, `kill`).

---

## 1. Process Routing & Markers (`bgRouting.ts` & `bg.ts`)

Background execution is initiated via the `--bg` flag [src/cli/bg.test.ts:117] or background-specific CLI subcommands. To prevent background child processes from recursively spawning or misidentifying their operational context, OpenClaude uses cryptographic process markers and strict environment variable passing.

### Process Markers and Environment Variables
When a background session is spawned, `src/cli/bgRouting.ts` generates a 256-bit cryptographic entropy marker (`--openclaude-bg-session-marker=<hex>`) [src/cli/bgRouting.ts:12-34]. This marker uniquely identifies the parent-child lineage.

The following internal environment variables are configured during background process launch (`src/cli/bgRouting.ts:3-10`):
* `OPENCLAUDE_INTERNAL_BACKGROUND_SESSION_ID`: The unique UUID assigned to the background session.
* `OPENCLAUDE_INTERNAL_BACKGROUND_LAUNCHER_PID`: The Process ID of the invoking shell/launcher.
* `OPENCLAUDE_INTERNAL_BACKGROUND_CLEANUP_WORKER`: Flag indicating if the current execution context is the background session cleanup worker.
* `OPENCLAUDE_INTERNAL_BACKGROUND_CLEANUP_OWNER_PID`: Owner PID for cleanup isolation.

## 2. Background Session Registry (`bgRegistry.ts`)

The background session registry (`src/cli/bgRegistry.ts`) manages persistent metadata, name reservations, and state tracking under the user's configuration directory (typically `~/.config/openclaude/bg-sessions/`) [src/cli/bgRegistry.ts:194-224].

### Directory Structure & States
The registry organizes state into discrete file-system partitions:
* `sessions/`: JSON metadata for each background session (`BackgroundSession`).
* `logs/`: `.out.log` and `.err.log` files capturing stdout and stderr streams.
* `names/`: SHA-256 digested name reservation records preventing collision on human-readable session names.
* `terminal/`: Fact files recording how and when a session terminated.

Valid `BackgroundSessionStatus` types include (`src/cli/bgRegistry.ts:42-49`):
* `running`: Process liveness check (`isProcessRunning`) confirms PID existence.
* `exited`: Process finished with exit code `0`.
* `failed`: Process finished with a non-zero exit code.
* `killed`: Terminated explicitly via `kill` command or signal.
* `stale`: Metadata exists but process is dead and no terminal fact was recorded.
* `unknown`: State cannot be resolved.

Sources: `src/cli/bgRegistry.ts:42-127()`, `src/cli/bgRegistry.ts:194-224()`

## 3. Finalizer & Terminal Facts (`bgFinalizer.ts`)

Every background process bootstraps a finalizer hook via `prepareBackgroundSessionFinalizer()` [src/cli/bgFinalizer.ts:40]. The finalizer guarantees that the process writes a durable "terminal fact" upon exit, regardless of whether termination is normal, exceptional, or triggered by an OS signal.

### Terminal Fact Generation
When a background session exits, `recordBackgroundSessionNaturalTermination()` or its synchronous counterpart writes a JSON payload to the `terminal/` directory (`src/cli/bgRegistry.ts`). This record includes:
* `version`: Schema version (`1`) [src/cli/bgRegistry.ts:78].
* `id`: Background session UUID [src/cli/bgRegistry.ts:79].
* `pid`: Process ID [src/cli/bgRegistry.ts:80].
* `status`: Final state (`exited`, `failed`, `killed`) [src/cli/bgRegistry.ts:82].
* `terminalReason`: Categorized as `exit_code`, `signal`, or `explicit_kill` [src/cli/bgRegistry.ts:72-76].

## 4. Background Cleanup Worker

To prevent indefinite accumulation of completed session logs and stale metadata, OpenClaude executes an out-of-process background cleanup worker (`runBackgroundSessionCleanupWorker` in `src/cli/bgFinalizer.ts`).

The cleanup worker is spawned during finalization if `cleanupPeriodDays` limits are exceeded or when explicit retention passes execute. It reads active locks, purges expired terminal facts, unlinks log files for deleted sessions, and updates the recovery journal (`.recovery-journal`) safely across multiple concurrent CLI invocations using file-system locking mechanisms (`src/utils/lockfile.js`).

Sources: `src/cli/bgFinalizer.ts:8-13()`, `src/skills/bundled/updateConfig.ts:117-117()`

## 5. CLI Handlers (`ps`, `logs`, `attach`, `kill`)

Users interact with background sessions through dedicated CLI handlers implemented in `src/cli/bg.ts`.

### Handler Overview
* **`ps` Handler**: Invokes `listBackgroundSessions()` and `refreshBackgroundSessionStatuses()` to output a formatted table of all active and recently completed background sessions, including PIDs, runtimes, models, and session IDs.
* **`logs` Handler**: Uses `followLogFile()` or `printExistingLog()` to stream stdout/stderr logs from disk chunk-by-chunk (`LOG_STREAM_CHUNK_SIZE = 64 * 1024`) supporting follow (`-f`) polling loops (`src/cli/bg.ts:87-130`).
* **`attach` Handler**: Resolves a background session identifier and connects the user's terminal back into the active session conversation or transcript view.
* **`kill` Handler**: Safely terminates the background session and its child process tree using `tree-kill` (`src/cli/bg.ts:6`), enforcing graceful termination grace periods (`DEFAULT_TERM_GRACE_MS = 2_000`, `DEFAULT_KILL_GRACE_MS = 2_000`) before sending `SIGKILL`.

Sources: `src/cli/bg.ts:1-53()`, `src/cli/bg.ts:87-130()`
