The Messages and Transcript Model manages the lifecycle, normalization, transformation, diffing, caching, and serialization of conversational turns within OpenClaude. It bridges raw user inputs, tool outputs, system boundaries, and model-specific constraints (such as Anthropic native formats versus OpenAI or custom provider shims).

---

## 1. Message Factories & Core Message Types

OpenClaude defines structured message types (`UserMessage`, `AssistantMessage`, `AttachmentMessage`, and various `SystemMessage` subtypes) [src/utils/messages.ts:46-75](). Specialized factory functions construct these types with robust defaults, auto-generated UUIDs, and timestamps (`src/utils/messages/factories.ts`) [src/utils/messages/factories.ts:91-145]().

- `createUserMessage`: Instantiates a user turn with metadata such as `isMeta` and `isSidechain` [src/utils/messages.ts:157]().
- `createAssistantMessage`: Instantiates model responses containing text blocks, thinking blocks, or tool execution requests [src/utils/messages/factories.ts:147-169]().
- `createAttachmentMessage`: Injects local file context, code patches, or auxiliary inputs into the transcript.
- `createAssistantAPIErrorMessage`: Wraps provider-level API failures into synthetic assistant response structures [src/utils/messages/factories.ts:171-194]().

## 2. Normalization & Tool-Result Pairing

Before dispatching transcripts to upstream APIs or storing them to disk, messages pass through validation and normalization layers (`normalizeMessages`, `normalizeMessagesCached`, and `normalizeMessagesForAPI`) [src/utils/conversationRecovery.ts:40](), [src/utils/messages/normalize.ts:54-167]().

The normalization subsystem enforces strict tool-result pairing (`validateToolResultPairing`) [src/utils/messages.ts:163-167](). If a tool call lacks its corresponding result—or if an orphaned tool result appears due to compaction truncation or away-summary projections—the engine drops or repairs the pairing to prevent upstream schema rejection.

## 3. Content Processing & API Transformation

The API transformation module (`src/utils/messages/apiTransform.ts`) adapts internal message formats to specific provider requirements. It handles:
- Stripping or preserving `thinking` and `redacted_thinking` blocks depending on whether the target provider is Anthropic-native or an OpenAI/third-party shim [src/utils/conversationRecovery.hooks.test.ts:100-117]().
- Appending message identification tags (`appendMessageTagToUserMessage`) for history snip boundaries [src/utils/messages.ts:175]().
- Stripping caller fields from assistant messages (`stripCallerFieldFromAssistantMessage`) [src/utils/messages.ts:177]().
- Removing oversized images or media attachments on retry following prompt-too-long or vision-rejection API errors (`getImageTooLargeErrorMessage`) [src/utils/messages/apiTransform.test.ts:44-72]().

Sources: `src/utils/messages/apiTransform.ts`, `src/utils/messages.ts:175-180`, `src/utils/conversationRecovery.hooks.test.ts:100-197`, `src/utils/messages/apiTransform.test.ts:44-72`

## 4. Diffs & Line Calculations

The diff utility (`src/utils/diff.ts`) computes line changes (`countLinesChanged`) for added or modified files during code-editing tool executions. It accounts for trailing newlines and platform-specific line endings (CRLF vs. LF) to match git-compatible metrics before aggregating stats into session context counters [src/utils/diff.test.ts:67-85](). Additionally, `gitDiff.ts` provides `parseGitDiff` and `parseRawDiffToToolUseDiff` to process patches and enforce 1MB size bounds [src/utils/gitDiff.ts:200-213]().

Sources: `src/utils/diff.ts`, `src/utils/diff.test.ts:67-85`, `src/utils/gitDiff.ts:114-213`

## 5. Session History Serialization & Recovery

Conversation transcripts persist to disk as JSONL files. The recovery and serialization layer (`sessionHistorySerialization.ts` and `conversationRecovery.ts`) reconstructs these logs into active runtime states.

- `loadConversationForResume`: Parses log files, migrates legacy attachment structures (`migrateLegacyAttachmentTypes`), and enforces size boundaries (`assertResumeMessageSize`) [src/utils/conversationRecovery.ts:103-112]().
- `ResumeTranscriptTooLargeError`: Throws an explicit error if a reconstructed transcript exceeds `MAX_RESUME_MESSAGE_BYTES` (8 MiB) to prevent memory exhaustion during startup [src/utils/conversationRecovery.ts:88-101]().

## 6. Conversation Cache

To eliminate redundant parsing overhead and minimize memory usage during rapid message traversals, OpenClaude provides an LRU cache (`ConversationCache`) implemented using a JavaScript `Map` for $O(1)$ access order tracking (`src/utils/conversationCache.ts`).

The cache supports time-to-live (`ttlMs`), maximum size caps (`maxSize`), and a monotonic logical clock (`accessClock`) to guarantee correct LRU eviction even under heavy concurrent accesses.
